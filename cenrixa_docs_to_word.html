CENRIXA - Full-stack Training Management System

Welcome to the detailed documentation for CENRIXA, a robust, modular, and secure training management system designed for modern enterprise workflows. This document explains the architecture, the integration of independent packages, the role of Keycloak as an auth federator, and the core logic behind the project.

1. Project Overview & Objectives

CENRIXA is built to manage the end-to-end lifecycle of training programs. Its primary goal is to provide a seamless experience for:

  • Administrators: To manage users, roles, and global configurations.
  • Managers: To assign tasks and review submissions from their teams.
  • Trainees: To execute assigned tasks and track their learning progress.

The system is designed with security first, utilizing multiple layers of authentication and authorization.

2. The Modular Architecture

CENRIXA is not a monolithic application. It is a combination of three independent Python packages that work together under the orchestrator (FastAPI backend).

2.1 The Three Core Packages

Package Purpose Responsibility
keycloak_auth Authentication Validates JWT tokens, caches public keys (JWKS), and handles token exchange with Keycloak.
rbac_system Authorization Manages dynamic roles and permissions (RBAC). It ensures that a "Manager" can only do what a manager is allowed to do.
taskflow_system Business Workflow Manages the lifecycle of tasks (In Progress, Under Review, Completed). It is the "brain" of the training process.

2.2 Independence & Reusability

Each package is developed as a standalone Python library (with its own setup.py or project.toml). They are "loosely coupled," meaning:

  • rbac_system doesn't need to know keycloak_auth exists.
  • taskflow_system can be used in a different project entirely with zero changes.
  • The Combination: The training_portal backend imports all three and stitches them together.

3. Keycloak: The Auth Federator

In this project, Keycloak acts as a "Federator" or "Identity Broker." This is a major architectural advantage.

3.1 How it Works in CENRIXA

Instead of users logging in directly with local credentials, Keycloak delegates authentication to professional providers like Okta or Google.

  1. Unified Entry Point: Users always see the Keycloak login screen.
  2. Federation: Keycloak is "linked" to Okta/Google. When a user clicks "Login with Okta," Keycloak redirects the user to the Okta sign-in page.
  3. Token Normalization: Regardless of whether the user used Google or Okta, Keycloak returns a standardized JWT (JSON Web Token) to the CENRIXA backend. Our backend only needs to trust Keycloak!

4. PostgreSQL Integration

CENRIXA uses PostgreSQL as its enterprise-grade data store. There are two distinct integrations:

  1. Keycloak Backend Store (keycloak_db):
    • Keycloak itself requires a database to store realms, clients, users (federated), and sessions.
    • Integrated via conf/keycloak.conf using the JDBC URL: jdbc:postgresql://localhost:5432/keycloak_db.
  2. Application Store (training_portal):
    • The rbac_system and taskflow_system store their roles, permissions, tasks, and trainees here.
    • The backend uses sqlalchemy with asyncpg for high-performance database access.

5. Logic Locations: Where the "Brains" Are

Feature Core Logic (The "Brain") Dependency Layer
Authentication keycloak_auth/core.py: JWT validation, signature verification. keycloak_auth/fastapi_utils.py: Middleware for FastAPI.
Access Control rbac_system/engine.py: Rules for who can see what. rbac_system/repository.py: CRUD for roles/perms.
Task Workflow taskflow_system/service.py: State transitions (e.g., Backlog -> Success). taskflow_system/repository.py: CRUD for tasks/submissions.

6. Registration & The 3 Dashboards

6.1 Registration & Sync Flow

CENRIXA uses a "Secure Registration" flow:

  1. First Login: When a user logs in via Okta/Google for the first time, Keycloak informs our backend.
  2. Local Sync: The backend creates a record in our local User table.
  3. Status Check: Default new users are PENDING; Admin approval is required.

6.2 The Three Dashboards

Dashboard Main Logic Location Key Capability
Admin api/admin.py User approval, Role assignment, System health.
Manager api/manager.py Create training tasks, Review trainee work.
Trainee api/trainee.py Execute tasks, Submit work for review.
